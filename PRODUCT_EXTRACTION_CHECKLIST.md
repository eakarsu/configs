# Product extraction checklist

Do not modify this archive into an application. Create a separate repository and complete every item before using a selected configuration:

- Name the product owner, security owner, target users, supported workflow, and measurable acceptance criteria.
- Record the source filename and digest; review every prompt, sample record, field, and generated target instead of bulk-copying variants.
- Obtain an explicit project license and verify rights for data, names, prompts, dependencies, media, and provider use.
- Define a versioned input schema, bounded parser, migration/update policy, configuration contract, and failure behavior.
- Build secure identity and tenant/role boundaries, authoritative persistence, auditable state transitions, secret management, and provider allowlists.
- Remove or replace demo/sample behavior and validate domain rules with qualified owners where the subject is regulated or safety-critical.
- Add unit, integration, end-to-end, migration, abuse/failure, security, accessibility, and recovery tests plus CI and a reproducible release artifact.
- Document monitoring, incident response, backup/restore, retention/deletion, rollback, dependency patching, and decommissioning.
- Run legal, privacy, security, operations, and representative-user launch reviews. Record external blockers rather than claiming they were solved in source.
